# 背包系统设计

* 玩家单人持有的默认背包由 物品栏、背包 构成

* 背包中物品使用：
    * 背包打开时，在下方显示一个物品栏条（参考minecraft），可以将物品拖拽到此物品栏中配置物品栏持有项目，也可以点击菜单中的装配来设置为物品栏物品。设置后，背包中这个物品变为物品栏的物品，转移过去，物品栏也是一条特殊的背包，配置物品栏 相当于将背包内容持有给了物品栏。
    * 点击使用，是先给与玩家Ability，根据物品的配置（长按或点击）激活，完成后关闭能力。而不是现在的持有
* 物品栏中物品使用：
    * 1-9切换手持物品，此时会出现物品对应模型在手（史莱姆对应口）部位，物品没有碰撞和移动，纯粹根据Actor的嵌套方式进行计算坐标
    * 使用流程：手持物品时，物品会给与玩家Ability，根据物品的配置（长按或点击）激活，完成后关闭能力
    * 长按时，必须使用 圆形倒计时UI 来表现，倒计时结束时Active Ability
    * 手持物品不需要额外在玩家上方的UI显示一下 圆形倒计时

# 物品设计

* 说明物品定义的文档格式如下：
    * @i <物品名称>: <说明>
        * M: <模型说明，手持、掉落时使用一套模型>
        * I: <物品Icon说明>
        * F: <物品使用功能>
        * G: <分类>
        * N: <堆叠上限>
        * R: <是否有耐久，有的话耐久度，0或不写为无>
        * AM: <弹药位：吃哪几种弹药、装几发，不写为不吃弹药，见「物品的弹药配置」>

# 物品的弹药配置

弹药不是「用掉就没了的一摞货」，它是**装在某一件东西上的**：同一把弓，装着 12 支箭和
空着是两种状态，而这两种状态属于**那一把弓**，不属于「弓」这个种类。所以弹药记在
**格子**上，不记在物品目录里。

## 谁能装、装什么、装多少

* `@i` 多一个字段 `AM`（弹药位），不写就是这件东西不吃弹药：
    * `AM: <弹药名称>[ / <弹药名称>…] ×<容量>`，例：`AM: 箭 ×12`
* **只有 `N: 1` 的物品能写 `AM`。** 一格里堆着两把弓时，装进去的箭归哪一把答不上来；
  这不是限制，是「弹药属于那一件」成立的前提。
* 弹药那一侧**不需要任何字段**：`AM` 写的是**物品名称**，不是分类——「什么算弹药」由
  吃它的那件东西说了算。弹弓吃的就是普通石头，而石头是材料。同一种弹药可以被多种武器接受。
* 第一件带 `AM` 的东西是 `@i 弹弓`（`AM: 石头 ×5`），它和这一节一起落地。

## 装填

* 装填是一次**拖拽**：把一摞弹药拖到能吃它的那一格上。
* 「位于容器内」指的是**装得下它的任何一本账**——背包、物品栏、箱子用的是同一种格子，
  这条规则只写一遍，三处一起成立。
* 一次拖拽尽量装满：装到容量或来源那一摞见底为止，装不下的原样留在来源那一格。
* 拖拽现在的含义是「搬」（装配 / 排序 / 收回）。多出来的这一条按**来源与目标**判：
  来源是弹药、且目标的 `AM` 收这种弹药 → 装填；其余情况仍然是搬。这一条优先，否则把箭
  拖到弓上会变成两格对调。
* **装了弹药的那一格不和同类合并。** 它已经不是「一把普通的弓」了，合并会让弹药凭空
  变成两份或一份。

## 卸下

* 菜单里多一条「卸下弹药」，只在这一格真的装着弹药时点得动。
* 卸下的弹药按**拾取的落点顺序**回身上：先手上、再物品栏、最后背包。**一发都收不下时
  整件事不做**，弹药留在武器上——凭空消失比装不下更糟。
* 弹药跟着那一格走：装配到物品栏、收回背包、存进箱子，弹药都在。**丢到地上**时它记在
  那个掉落物身上，捡回来还在——否则丢一次弓等于弹药蒸发。

## 界面

* 格子右下角一个小方框：弹药图标 + 剩余发数。**空着时不画这个框**——一个空框看起来像
  坏了，而不像「没装」。
* 小框画在格子上，而格子只有一套，所以背包、物品栏、箱子三处长得一样、行为一样。

## 权威

* 弹药配置是**账本状态**，不是表现：随背包快照下发，客户端只画不猜。
* 两条命令：`ammo:load{目标格, 来源格}`、`ammo:unload{目标格}`。「哪一格」在三处是同一个
  形状（界面的 `InventorySlotRef`、命令里的地址、账本的 `entryAt`），所以命令过网不用翻译。
  装得下几发、来源够不够、收不收得回，都由服务端算。

## 落地要动的地方

| 去处 | 做什么 |
| --- | --- |
| `config/items/item-catalog.schema.json` | 加 `ammo: { accepts: [id], capacity }`，只允许 `stackLimit: 1` 的物品写 |
| `ItemLedger` / `InventoryComponent` | 格子多一段 `ammo: { itemType, quantity }`；带弹药的格子不参与合并 |
| 玩家快照 | 背包与物品栏各带上这一段；箱子那份跟着容器快照 |
| `messages.ts` / `ServerScene` | `ammo:load` / `ammo:unload` 两条命令 |
| `InventorySlotCell` / `InventoryPage` | 拖拽多一条装填分支、格子多一个弹药小框、菜单多一条「卸下弹药」 |
| `ItemStackComponent` | 掉落物还没有弹药位。**丢下装着弹药的东西时先把弹药卸回身上**（收不下的那些跟着掉在地上），所以现在也不会蒸发；等掉落物真的能记住「哪一件」再改成跟着走 |
